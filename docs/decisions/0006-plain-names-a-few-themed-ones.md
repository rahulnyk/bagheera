# Plain names, with Jungle Book names for a few top-level components

## Context and problem statement

PRD §8 asks for a light Jungle Book theme: themed names only for a few top-level things where a name helps people talk about them, and plain names for agents, commands, skills, files and workflows.

## Considered options

* Themed names only for the product
* Plain names, plus themed names for a few top-level components
* Jungle Book names for everything

## Decision outcome

Chosen option: plain names, plus themed names for a few top-level components.

* Commands, skills, agents, files and workflows get plain, descriptive names.
* A handful of top-level components may get a themed name, each proposed to the owner first, shown with its plain name, and recorded in the naming register in [design/README.md](../design/README.md#naming-register).
* `seeonee` is the placeholder GitHub org until the real one is known (PRD Q1).

### Consequences

* Good, because a few memorable names help people talk about the main components.
* Bad, because each themed name is one more word to learn; showing the plain name beside it is the guard.
